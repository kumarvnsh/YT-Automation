# Daily 3D implementation plan

**Goal:** Make the approved camera-led 3D style usable by daily Histold Shorts, with a persistent GitHub toggle back to existing 2D, and publish a newly researched video to every connected target.

**Architecture:** Keep `video.mode` as the existing 2D selection. An optional `video.three_d.enabled` plus repository variable `HISTOLD_3D` selects `three_motion` for new Shorts. Snapshot the effective selection per stage. Reuse research, script, native Kokoro timing, captions, composition, quality, upload and state persistence. The new renderer asks the existing scene model for a validated declarative 3D diorama and camera-shot plan, renders local Three.js using pinned HyperFrames, and saves measured visual checks. No hardcoded Roman narration, artifact downloads or publishing credentials in the renderer.

**Tech stack:** Existing Python pipeline, Three.js, HyperFrames, Node 22, FFmpeg, existing Anthropic scene model and native Kokoro timing.

- [ ] Write failing tests for toggle precedence, 2D restoration, stable resume mode and render dispatch.
- [ ] Wire the mode into pipeline, production workflow and one-command GitHub toggle.
- [ ] Write failing tests for declarative scene validation, camera coverage and caption-safe composition.
- [ ] Build reusable primitive/composite geometry, timed camera tour, paths and animations; validate and persist scene plans.
- [ ] Run meaningful existing and new tests; review integration and uploader retry behavior.
- [ ] Render a newly researched topic via the normal GitHub pipeline without publishing, inspect the artifact and quality reports.
- [ ] Integrate verified changes into the daily workflow and enable 3D.
- [ ] Publish the reviewed new video once to YouTube, Facebook and Instagram using existing resumable upload logic; confirm platform IDs/links and report partial failures honestly.

User authorization includes integration, enabling daily use and publishing the new video. Existing drafts, unrelated working-tree changes and previously published videos must be preserved. Stories remain controlled by the existing configuration. Publishing must not duplicate successful platform uploads on retry. All quality failures must be resolved before this publication. A 3D toggle-off restores the existing mode; an in-flight 3D job retains its mode.
